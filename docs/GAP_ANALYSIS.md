# Gap Analysis

| Area | Current implementation | Target implementation | Gap | Difficulty | Risk | Recommended first step |
|---|---|---|---|---|---|---|
| Health checks | `--scan` checks candidate Google IPs. Startup logs warmup and CA status. Exit nodes expose GET health endpoints. | First-class `doctor/status` command checking local ports, Google front, Apps Script auth, exit node, CA trust, config, and risky settings. | No unified diagnostics command or status model. | Medium | Low if read-only and timeout-bound. | Add a diagnostics module that loads config and reports checks without starting proxy listeners. |
| CLI commands | `main.py` supports start-by-default, cert install/uninstall, scan, port/host overrides, log level. | Subcommands such as `start`, `doctor`, `status`, while preserving `python main.py`. | CLI is flat and startup-oriented. | Medium | Medium due backward compatibility. | Add optional subcommand parsing while preserving current flags. |
| Config validation | JSON loaded as dict. Some required fields checked in `main.py`; numeric values normalized locally. | Versioned config schema with errors/warnings and security linting. | No complete schema, no unknown-field warnings, no consolidated validation report. | Medium | Low to medium. | Add warning-only validator used by doctor first. |
| Policy routing | Rules are spread across `block_hosts`, `direct_hosts`, `bypass_hosts`, `hosts`, Google constants, SNI rewrite suffixes, relay URL patterns, and exit-node host rules. | Explicit policy router returning route action, reason, and selected transport. | Routing is coupled to `ProxyServer._handle_target_tunnel()` and `DomainFronter`. | High | High if behavior changes without tests. | Extract pure domain/IP matching and route-decision tests before runtime changes. |
| Sensitive-domain protection | No first-class sensitive domain category. Direct bypass can be configured manually. | Built-in/user-configurable sensitive domains direct/no-MITM by default. | Current default may MITM sensitive HTTPS domains. | Medium | High security impact. | Add sensitive-domain list in config model and warn in doctor before enforcing. |
| Direct bypass | `bypass_hosts`, `direct_hosts`, default local suffixes, Google direct shortcut, and non-HTTP direct tunnel exist. | Deterministic direct bypass policy including local/private IPs and domestic domains when configured. | Host suffix bypass exists, but private IP/domestic logic is not centralized. | Medium | Medium. | Add pure `is_private_or_local_destination()` and tests. |
| MITM safety | MITM CA generated and auto-installed unless skipped. CA private key stored under `ca/`. | No-MITM defaults where possible, explicit warnings, sensitive no-MITM, safer CA docs. | MITM is central and automatic in current startup. | High | High. | Add doctor warnings and policy bypass before changing startup default. |
| Transport abstraction | Apps Script client and exit-node chaining live inside `DomainFronter`. Direct/SNI/MITM logic live in `ProxyServer`. | `Transport` interface with `AppsScriptTransport`, `DirectTransport`, `ExitNodeTransport`, future transports. | No explicit interface; routing and transport execution are mixed. | High | High. | Define minimal interface in docs/tests first, then wrap Apps Script without moving behavior. |
| TUN/tun2socks full-system mode | Not present. SOCKS5 listener exists and can be a tun2socks target. | Experimental system mode: TUN adapter -> tun2socks -> local SOCKS5 -> policy router. | No TUN lifecycle, route management, admin checks, or rollback. | High | High; can break connectivity. | Defer until doctor and policy routing are stable; design Windows wrapper first. |
| DNS handling | System DNS plus optional `hosts` override map. SOCKS5 can receive domain names. | DNS policy layer and future local resolver. | No DNS interception, DNS routing, or leak controls. | High | Medium to high. | Document DNS limitations; add local/private IP handling before resolver work. |
| Logging | Pretty logs, component names, response summaries, execution count, some script ID masking. | Redacted route logs, doctor output, optional structured logs, consistent secret redaction. | Redaction is not centralized; route decisions are not uniformly logged. | Medium | Medium. | Add central redaction helper and route-decision log format. |
| Error handling | Many local try/except blocks, timeouts, fallback from H2 to H1, exit-node fallback to Apps Script. | Typed errors for config, transport, policy, and diagnostics. | Error handling is practical but scattered. | Medium | Medium. | Start with typed doctor result objects and config validation errors. |
| Cross-platform support | Local proxy supports Windows/Linux/macOS. Cert install supports Windows/macOS/Linux/Firefox. VPS exit node Linux only. Docker present. | Windows-first TUN, Linux experimental, current proxy preserved, Android out of scope. | Full-system platform support absent. | High | High. | Keep TUN behind explicit platform checks and opt-in. |
| Exit node handling | Optional chained relay through Apps Script to Cloudflare/Deno/VPS URL. `full` or `selective` mode. | First-class exit-node transport or chained transport selected by policy. | Exit-node policy and transport execution are embedded in `DomainFronter`. | Medium to high | Medium. | Extract exit-node match logic into pure policy tests. |
| Documentation | Existing docs cover getting started, config, architecture, security, troubleshooting, Docker, LAN, exit node. | Production roadmap, target architecture, PRD, gap analysis, implementation plan. | Existing docs are user setup oriented, not a fork roadmap. | Low | Low. | Add the new planning docs. |
| Test coverage | Unit tests cover helper modules: proxy support, fronting support, codec, adblock. | Tests for config validation, policy routing, sensitive bypass, doctor, transport contract, TUN wrapper safety. | No tests for core routing or relay integration boundaries. | Medium | Medium. | Add pure unit tests for policy/router before behavioral changes. |
